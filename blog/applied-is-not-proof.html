“Applied” is not proof

Our AI system reported a fix as applied. The record of what was actually written said something else. This is the check that caught it, and why we now run it after every automated change.

What happened

We run an AI system that investigates support cases for a membership marketplace. It reads the member’s records, finds the cause, and proposes a fix as a short plan. A person approves each step before anything is written.

Two cases that day needed four changes to members’ subscriptions. One of them was an end date. The plan proposed 30 October 2027. The person approved it. The screen showed “Applied”, with the proposed date printed next to it.

The value written to the member’s record was 29 November 2027.

Why the screen was wrong

The plan and the write were two different pieces of software. The plan showed what the AI had proposed. The write went through an approval window, and that window had its own rule for date fields: start from the current value and add 30 days. It replaced the proposed date with its own default. The new value was visible in the window, and the approval went through anyway.

Nothing failed. No error was logged. Every part did what it was built to do, and the member ended up with a wrong date under an “Applied” label.

What caught it

Every write in this system leaves a receipt: the value before and the value that was sent. Before telling the marketplace owner the case was closed, we read the receipt for each step and compared it with the plan. Three steps matched. One did not.

The same receipt made the repair simple. It held the previous value, so the change was undone through the product. The approval window was fixed the same day.

The rule we took from it

  1. A status label describes the intention. Only the record of what was sent describes the action.
  2. Every automated write stores the value before and the value sent, so it can be compared and undone.
  3. Nobody reports a change as done until the receipt has been compared with the plan, step by step.
  4. After an undo, check the live record too. A cached copy can keep showing the old state.

This is most of what separates an AI demo from an AI system a business can rely on. The model was right in this case. The surrounding software was wrong, and only a plain written record made that visible before a customer was told something false.
